Environment: staging · Role: user · Test type: both

## Risks

| ID  | Risk                                                                                                                  | Impact | Likelihood | Level  |
| --- | --------------------------------------------------------------------------------------------------------------------- | ------ | ---------- | ------ |
| R1  | Event creation, retrieval, update, or deletion corrupts or returns incorrect event state.                             | High   | Medium     | High   |
| R2  | Event filters return incomplete or incorrectly filtered results.                                                      | Medium | Medium     | Medium |
| R3  | Invalid or incomplete event input is accepted, or valid event data is rejected.                                       | High   | Low        | Medium |
| R4  | The documented public event-list endpoint rejects callers without a token in staging.                                 | Medium | High       | High   |
| R5  | Parallel tests creating events for the shared user can reach the six-event limit and replace the user's oldest event. | High   | Medium     | High   |

## Open questions

- Product decision required: OpenAPI declares no security requirement for `GET /events`, so the contract expectation is HTTP 200 without a token; a curl request without a token reproduced HTTP 401 on staging. Decide whether the contract or implementation should change. Keep the test expectation contract-based until decided.
- DELETE documentation states that associated bookings are deleted by cascade. The planned lifecycle case uses an event with no associated bookings to avoid collateral staging data changes; cascade behavior is not exercised by these cases.
- Staging finding: API event search works, but the Events UI search field did not filter the list. Search is intentionally not a UI case; confirm whether the UI failure should be tracked as a product defect.
- The authenticated `/admin/events` page indicates a six-event-per-user limit and replaces the oldest event at the limit. Parallel tests that create events for the shared `user` could overwrite existing data; confirm the account has safe capacity or that event-creating runs will be serialized.
- Approval required before implementation: add a project fixture in `src/fixtures/test-fixtures.ts` that obtains `apiTokenFor("user")`, uses `addInitScript` to set localStorage `eventhub_token` before navigation, and supplies the authenticated Page to the Events Page Objects. This is a new project abstraction.
- Combined category-and-city filtering was not confirmed on staging and is intentionally excluded from T016.
