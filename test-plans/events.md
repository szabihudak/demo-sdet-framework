# Events test plan

Environment: staging · Role: user · Test type: API

## Risks

| ID  | Risk                                                                                      | Impact | Likelihood | Level  |
| --- | ----------------------------------------------------------------------------------------- | ------ | ---------- | ------ |
| R1  | Event creation, retrieval, update, or deletion corrupts or returns incorrect event state. | High   | Medium     | High   |
| R2  | Event filters or pagination return incomplete or incorrectly paginated results.           | Medium | Medium     | Medium |
| R3  | Invalid or incomplete event input is accepted, or valid event data is rejected.           | High   | Low        | Medium |
| R4  | The documented public event-list endpoint rejects callers without a token in staging.     | Medium | High       | High   |

## Open questions

- Product decision required: OpenAPI declares no security requirement for `GET /events`, so the contract expectation is HTTP 200 without a token; a curl request without a token reproduced HTTP 401 on staging. Decide whether the contract or implementation should change. Keep the test expectation contract-based until decided.
- DELETE documentation states that associated bookings are deleted by cascade. The planned lifecycle case uses an event with no associated bookings to avoid collateral staging data changes; cascade behavior is not exercised by these cases.
